# Bermuda 0.8.2 — Linux packages and Windows preview

Bermuda is a desktop application for studying Go games, searching local board
patterns and comparing continuations from game records.

**This is a pre-release for testers, not a general stable release.** The RPM and
Flatpak have been installed and tested by the maintainer on openSUSE Tumbleweed.
The first Windows package has passed automated build, startup and KataGo checks
on GitHub's Windows Server runner. **It has not yet been tested interactively on
a clean Windows 11 PC.** Windows users are invited to help test it.

## Windows package revision 1

The initial Windows 0.8.2 preview could fail to open an SGF because file dialogs
passed `/C:/...` to Windows instead of `C:/...`. Revision **0.8.2-1** corrects
SGF open/save and database folder selection, and adds an automated real-SGF open
check. Its About dialog identifies the revision as 0.8.2-1. The Linux downloads
are unchanged. Windows 11 user validation of the corrected package is pending.

## Changes since 0.8.1

- Clearer study branching, with comments and either-colour branching from inserted nodes.
- Restored access to removing games from My Games.
- Improved startup presentation and clearing of stale KataGo analysis when changing positions.
- Improved guided KataGo setup, including access after an engine is already configured.
- Consistent Go-board launcher icon across the Linux and Windows packages.
- First Windows x64 ZIP, with application dependencies included.

## Windows preview: please read before downloading

Extract the **whole ZIP** into a folder, then open `Bermuda.exe`. Do not launch
from inside the ZIP or move the executable away from its accompanying folders.
Qt, Rust and development tools do not need to be installed. You may create a
Windows desktop shortcut to `Bermuda.exe`.

**The Windows executable is not Authenticode-signed.** Windows may display an
unknown-publisher or SmartScreen warning. The GPG-signed checksum list verifies
the downloaded ZIP; it does not provide Windows publisher recognition or remove
SmartScreen warnings. Obtain this preview from this project's release page.

The original preview passed automated checks on 6 October 2026: 240 core tests, packaged QML startup,
and a real analysis result after using Bermuda's guided CPU KataGo installer.
[Windows build and checks](https://github.com/gerryg1957/Bermuda/actions/runs/37452432424).
That original startup check did not exercise SGF file opening. The revised
workflow now does; its result should be checked in GitHub Actions before publishing
the corrected Windows asset. The runner contains developer tools; removing SDK search paths for the check is
not equivalent to testing on a clean Windows 11 installation.

Windows 11 testers should try importing a small SGF folder, opening games, pattern
search, study variations and comments, saving/reopening a study, file dialogs,
and guided KataGo setup followed by analysis after restarting Bermuda. Non-ASCII
usernames and folder names still need checking. Start with copies of your SGFs.
Windows ARM and 32-bit Windows are not supported by this package.

## Install the Tumbleweed RPM

Download the application RPM and public key. Inspect the key first:

```bash
gpg --show-keys --with-fingerprint ./bermuda-signing-key.asc
```

The Bermuda signing fingerprint is:

```text
671AE6477ACE75C95BC695A5EC2793D4263A81A4
```

After checking the fingerprint against the project's published key:

```bash
sudo rpm --import ./bermuda-signing-key.asc
rpm -Kv ./bermuda-0.8.2-1.x86_64.rpm
sudo zypper install ./bermuda-0.8.2-1.x86_64.rpm
```

Require `OK` for the signature and digests. Launch Bermuda from the application
menu, or run `/usr/bin/bermuda-qt` to select the RPM explicitly.

## Install the Flatpak

Install Flatpak through your distribution if needed, then:

```bash
flatpak remote-add --user --if-not-exists flathub \
  https://flathub.org/repo/flathub.flatpakrepo
flatpak install --user ./bermuda-0.8.2-x86_64-signed.flatpak
flatpak run org.bermuda.app//test
```

Flathub supplies the separate KDE runtime; Bermuda itself is not listed on
Flathub. Its menu entry is **Bermuda (Flatpak test)**. The Flatpak uses its own
profile under `~/.var/app/org.bermuda.app/` and does not automatically share the
RPM's settings or database. Use the file dialogs to select SGFs and folders.
Updates to this standalone bundle must be downloaded and installed explicitly.

## KataGo

Use **Set up KataGo → Install KataGo for me** for guided CPU/Eigen installation.
Bermuda selects a CPU-compatible download and manages the engine, network and
configuration paths. Experienced users can select their own engine and network.

Automatic GPU-engine installation and GPU/network recommendations are not part of
this release. Custom host GPU engines are not confirmed to work in the Flatpak
sandbox. The Windows automated check covers the CPU route selected by the runner,
not every CPU, GPU or interactive setup path.

## Verify release downloads

The RPM and Flatpak are signed with the Bermuda release key. All downloadable
packages, including the Windows ZIP, are covered by the signed checksum list.
After checking the public-key fingerprint, Linux users can run:

```bash
gpg --import ./bermuda-signing-key.asc
gpg --verify SHA256SUMS.asc SHA256SUMS
sha256sum --ignore-missing -c SHA256SUMS
```

Require a good signature from the expected key and `OK` for your downloaded
package. On Windows, `Get-FileHash .\bermuda-0.8.2-1-windows-x64.zip -Algorithm SHA256`
in PowerShell computes the ZIP hash for comparison with the supplied checksum.
A hash comparison alone checks integrity, not the publisher's identity.

## Remaining limitations and reporting problems

Clean-machine Linux dependency testing, other Linux distributions, and the full
Flatpak file-portal/export workflows are not yet fully validated. A complete
review of bundled third-party licences remains outstanding; licence texts
accompany the packages. These downloads are for testing, not a claim of broad
platform certification.

Please report issues at https://github.com/gerryg1957/Bermuda/issues with your OS,
package choice and version, reproduction steps and any error output. There is no
need to upload private game collections. Back up valuable studies before testing
a pre-release.
