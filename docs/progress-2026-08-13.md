Yes — I think the gaps are telling us something important: enclosure should behave as a region, not as 361 independent point judgements.

The current directional test can say “this point looks enclosed” and then make a different decision one intersection away because one ray happens to hit a different stone. That explains both the missing top-left points and the little holes along the right edge.

I would keep the present enclosure calculation as the source of strong seeds, then add a conservative region-coherence pass:

    strong Black/White enclosure remains as found;

    a weak or missing point may join a neighbouring enclosed region;

    it needs support from at least two orthogonal neighbours;

    a board edge counts as one support, which is particularly important for side/corner territory;

    it cannot spread into an area where the underlying influence clearly favours the opponent.

That should fill genuine holes without simply painting huge areas.

cd ~/moyodb

python3 - <<'PY'
from pathlib import Path

path = Path("moyodb-qt/src/qml/GoBoard.qml")
text = path.read_text()

old = '''        for (let y = 0; y < size; ++y) {
            for (let x = 0; x < size; ++x) {
                enclosure[y * size + x] =
                    enclosureAt(x, y)
            }
        }

        root.influenceValues = combined
        root.enclosureValues = enclosure
'''

new = '''        for (let y = 0; y < size; ++y) {
            for (let x = 0; x < size; ++x) {
                enclosure[y * size + x] =
                    enclosureAt(x, y)
            }
        }

        /*
         * Enclosure is a regional property. The directional test above
         * deliberately finds convincing individual points, but exact rays
         * can leave artificial one-point gaps between otherwise coherent
         * areas.
         *
         * Grow only from reasonably strong enclosure seeds. A candidate
         * needs support from two orthogonal directions. At the physical
         * board edge, the edge itself provides one item of support.
         *
         * Opposing influence prevents the enclosure from spreading through
         * a genuinely contested area.
         */
        function coherentEnclosurePass(source) {
            const result = source.slice()

            function valueAt(x, y) {
                if (x < 0 || x >= size || y < 0 || y >= size)
                    return null

                return Number(source[y * size + x])
            }

            for (let y = 0; y < size; ++y) {
                for (let x = 0; x < size; ++x) {
                    const index = y * size + x

                    if (occupied[index] !== "")
                        continue

                    /*
                     * Do not weaken a point already classified confidently.
                     */
                    if (Math.abs(source[index]) >= 0.45)
                        continue

                    let blackSupport = 0
                    let whiteSupport = 0
                    let blackStrength = 0.0
                    let whiteStrength = 0.0

                    const neighbours = [
                        [x - 1, y],
                        [x + 1, y],
                        [x, y - 1],
                        [x, y + 1]
                    ]

                    for (const neighbour of neighbours) {
                        const nx = neighbour[0]
                        const ny = neighbour[1]
                        const value = valueAt(nx, ny)

                        if (value === null) {
                            /*
                             * The edge supports continuity but has no colour.
                             * Its colour is inferred below from neighbouring
                             * enclosure evidence.
                             */
                            continue
                        }

                        if (value >= 0.45) {
                            ++blackSupport
                            blackStrength += value
                        } else if (value <= -0.45) {
                            ++whiteSupport
                            whiteStrength += -value
                        }
                    }

                    const touchesVerticalEdge =
                        x === 0 || x === size - 1
                    const touchesHorizontalEdge =
                        y === 0 || y === size - 1
                    const edgeSupport =
                        (touchesVerticalEdge ? 1 : 0)
                        + (touchesHorizontalEdge ? 1 : 0)

                    /*
                     * Decide which neighbouring region, if any, has a clear
                     * claim on this point.
                     */
                    if (blackSupport > 0
                            && whiteSupport === 0
                            && blackSupport + edgeSupport >= 2
                            && combined[index] > -0.18) {
                        const average =
                            blackStrength / blackSupport

                        result[index] =
                            Math.max(
                                Number(source[index]),
                                Math.min(0.82, average * 0.88)
                            )
                    } else if (whiteSupport > 0
                               && blackSupport === 0
                               && whiteSupport + edgeSupport >= 2
                               && combined[index] < 0.18) {
                        const average =
                            whiteStrength / whiteSupport

                        result[index] =
                            Math.min(
                                Number(source[index]),
                                -Math.min(0.82, average * 0.88)
                            )
                    }
                }
            }

            return result
        }

        /*
         * Two conservative passes allow a genuine enclosed area to become
         * coherent without allowing a seed to flood arbitrarily far into
         * the open board.
         */
        let coherentEnclosure =
            coherentEnclosurePass(enclosure)

        coherentEnclosure =
            coherentEnclosurePass(coherentEnclosure)

        root.influenceValues = combined
        root.enclosureValues = coherentEnclosure
'''

MoyoDB is primarily a professional-game database and pattern-study tool.

Its distinctive question is:

It should provide evidence which the user can interrogate rather than attempt to manufacture an authoritative strategic explanation.

The user's job is to decide what strategic lesson to draw from that evidence.

MoyoDB progress and workplan — 13 August 2026
Current position

MoyoDB now has a coherent professional-game study workflow:

    open and replay a professional game;

    select an interesting rectangular pattern directly on the board;

    search the professional database;

    inspect matching games and continuation frequencies;

    select a continuation;

    filter to the supporting games;

    open those games at the relevant occurrence and study what actually happened.

The project is therefore moving from proving the architecture towards consolidation, performance work, usability review and release readiness.
Project identity

MoyoDB is primarily a professional-game database and pattern-study tool.

Its distinctive question is:

    What did strong human players actually play in comparable positions?

It should provide evidence which the user can interrogate rather than attempt to manufacture an authoritative strategic explanation.

The user's job is to decide what strategic lesson to draw from that evidence.

KataGo may later be complementary by answering a different question:

    What does a very strong engine think about this exact whole-board position?

MoyoDB should not become a cut-price KataGo.

Influence and hypothetical-move experiments

An optional influence display has been developed using discrete board intersections.

Black and White influence are propagated separately, opposing stones obstruct propagation, and enclosure is estimated using escape resistance.

The display is useful as a study aid but is not intended to be a score estimator or authoritative Go evaluation.

Rust support also exists for applying one or two legal hypothetical moves to a cloned board without modifying the loaded game.

A reusable ReplyInfluenceAnalysis QML component remains in the project.

An experiment which automatically scanned and ranked all legal candidate moves was removed because it was beginning to duplicate a weak version of engine analysis.

The hypothetical-move infrastructure remains because it may still be useful for user-directed study.
Practical testing on 13 August

A real professional middle-game position was used to test pattern search.

Changing the selected rectangle naturally moved between:

    broad evidence from many related professional positions; and

    small collections of close analogues.

This is useful and should remain under user control rather than being hidden behind automatic pattern selection.

However, once exact group status, liberties, cuts and life-and-death details dominate, local pattern search becomes less explanatory.

The testing suggests that professional pattern search may be especially useful during the fuseki-to-middle-game transition.

This is a tendency rather than a hard cutoff.
Comparison with Moyo Go Studio

The same position was searched in the old Moyo Go Studio.

Moyo Go Studio found roughly the same number of comparable games and did not appear to provide materially greater strategic insight from the tactical position.

It was, however, considerably faster.

Given the age of Moyo Go Studio, this is impressive and gives MoyoDB a useful performance benchmark.

Further pattern-search optimisation therefore remains worthwhile.
Minor usability observations
Search-result sorting

The main game catalogue can be sorted by columns, while pattern-search results currently cannot.

This may occasionally help when a search returns hundreds of games, but it has little value for very small result sets.

Treat this as later polish.
Mini-board occurrence display

The small indication showing where the pattern occurred in a supporting game may or may not add enough value when opening the game already positions the user at the occurrence.

Keep it for now, but do not prioritise further work until ordinary use establishes its value.
